# `_fresh_full_injecagent` — authoritative source for §4.7's InjecAgent numbers

This directory is the source of every InjecAgent (DH + DS) number reported in
`paper/section_4_deployment.tex` §4.7 ("InjecAgent") and the corresponding
row in Table 1 (`paper/related_work_table.tex`).

## Provenance

Generated by `injecagent_runner.py` (repo root) run with `--full`, which
synthesizes the complete 1,054-case InjecAgent corpus (510 direct-harm ×
17 user tasks × 30 attacker instructions, 544 data-stealing × 17 × 32) and
replays each case's corrected **two-step** dispatch (source-read call, then
the destination/direct-harm call, in the same session) through the live
Kavach parliament server at `http://127.0.0.1:8088`. The two-step form is
the fix `section_4_deployment.tex` line ~279 refers to as "DH's dispatch
was corrected to this two-step form as a methodology fix, not a change to
any minister's detection logic" — this file is the corrected run; an
earlier, single-step DH-only run (`benchmarks/results_v2/injecagent_dell_dh/`)
predates that fix and should **not** be cited for any paper number.

Command used to reproduce (see `injecagent_runner.py --help` for flags):

```
python3 injecagent_runner.py --full \
  --cases benchmarks/data/attacker_cases_dh.jsonl \
  --parliament-url http://127.0.0.1:8088 \
  --output benchmarks/results_v2/_fresh_full_injecagent
```

## What's in `summary.json`

- `strict.tp = 544`, `strict.recall = 0.5161` → the paper's "544/1054
  (51.6%) strict recall" figure (Table 1, §4.7). All 544 strict hits are
  DS (`DS:*` categories, `recall_strict: 1.0`); every `DH:*` category shows
  `recall_strict: 0.0`, matching §4.7's "no individual minister reaches
  hard Block on a DH case."
- `loose.tp_block_or_escalate = 765`, giving DH(221) + DS(544) = 765; DH's
  loose 221/510 (43.3%) is `results.csv`'s `decided_by` breakdown restricted
  to `category` starting `DH` (see below), not derivable from this
  aggregate summary alone.
- `loose.fp_block_or_escalate = 371` → the paper's "371/1,054 (35.2%)"
  benign soft-escalate rate (§4.7).

## What's in `results.csv`

Per-case row with `test_kind` (attack/benign), `category`, top-level
`verdict`/`decided_by`, and each minister's own `_verdict` column. The
per-minister breakdowns quoted in §4.7 (CHANNEL 153, VAULT 34, EXECUTOR 17,
NAVIGATOR 17 on DH attacks; CHANNEL 248, EXECUTOR 62, NAVIGATOR 61 on
combined benign) are **`decided_by` counts** — the one minister the Speaker
credits per case under veto-priority ordering, mutually exclusive by
construction — not a count of every minister whose own `_verdict` column
shows a hit (that alternative convention gives EXECUTOR 34 and NAVIGATOR 51
on DH attacks instead, since 51 DH attack cases have two or more ministers
firing together). Both conventions are now stated explicitly in
§4.7's text; this file supports either computation. See
`benchmarks/results_v2/injecagent_full_1054_rerun_20260723/` for an
independent same-day re-run confirming these figures.
