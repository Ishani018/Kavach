# `injecagent_full_1054_rerun_20260723` — independent re-run, DH numbers reconciled to a real system change

## Why this run exists

Requested as an independent confirmation of `_fresh_full_injecagent/`
(the file that actually backs every InjecAgent number in
`paper/section_4_deployment.tex` §4.7 and Table 1), generated by running
the exact same command:

```
python3 injecagent_runner.py --full \
  --cases benchmarks/data/attacker_cases_dh.jsonl \
  --parliament-url http://127.0.0.1:8088 \
  --output benchmarks/results_v2/injecagent_full_1054_rerun_20260723 \
  --concurrency 2
```

## Result: it does NOT match — and that's a real, explained finding, not a bug

| | `_fresh_full_injecagent` (Jul 21 21:34) | this run (Jul 23 18:00) |
|---|---|---|
| strict TP (overall) | 544/1054 (51.6%) | 685/1054 (65.0%) |
| DH strict recall | 0% (all 3 categories) | 24–33% per category |
| DS strict recall | 100% (544/544) | 100% (544/544) — **unchanged** |
| loose (Block-or-Escalate) | 765/1054 | 867/1054 |

DS is identical across both runs. The entire divergence is DH, and DH
alone.

**Root cause, confirmed via git history, not guessed:** two real commits
landed on the live parliament server between the two runs:

```
3ea694a  2026-07-23 00:47  feat: generalize CHANNEL's hard-block path to novel destination tools
e016b15  2026-07-23 13:52  fix: CHANNEL taint no longer overrides provenance's confirmed-legitimate destinations
```

This is the exact fix `appendix_a_generalization.tex` already describes
in the CHANNEL generalization-audit bullet: *"we have since wired the
same shape-based fallback into the hard-block path (verified: a novel
tool with a shape-matched value, e.g. an IBAN, now correctly
hard-Blocks)."* That fix was verified against the AtriumOS audit
specifically; it had not yet been re-measured against the InjecAgent DH
corpus. This run is that re-measurement, and it shows the fix working:
CHANNEL (and knock-on effects on the other ministers' relative shares)
now catches real DH cases it used to miss entirely.

We ruled out a dispatch-methodology bug first: `injecagent_runner.py`'s
DH path is two-step (`dh_source_payload()` then `attack_payload()`, same
`session_id = case["id"]`, awaited sequentially within each case) in both
runs, since it's the same script file — there is no code path that could
silently regress to single-step dispatch, and `session_id` is unique per
case so there's no cross-case contamination under `--concurrency 2`.

## Decision: paper keeps the pre-fix numbers (the frozen `_fresh_full_injecagent` snapshot)

Every other number in `section_4_deployment.tex` §4 was measured before
this week's CHANNEL fix landed. Swapping in only the post-fix DH number
would leave the paper describing a mix of two different system states
under one evaluation section, which is worse than either single, clean
snapshot. `section_4_deployment.tex`'s DH paragraph now states this
explicitly: the reported DH numbers predate the fix, and re-measuring
after it is noted as immediate future work, not silently omitted.

This run's `results.csv`/`summary.json` are the record of the post-fix
state, kept for exactly that future re-measurement.
